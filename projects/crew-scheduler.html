Crew Scheduler — Sign-inRole-based signup: crew get scheduled and can pick up open shifts; manager access is gated by an access code.
Full-Stack Developer · Scheduling & Operations

As Director of Operations for CU Boulder’s Program Council, I built this staff scheduling platform for our events crew. Managers create events and assign shifts — including supervisor-tier and split shifts — while crew members set recurring weekly availability with per-date overrides, request time off, and pick up open shifts. A shift-swap marketplace with manager approval keeps coverage intact when plans change, an attendance and absence-reporting pipeline tracks who actually showed up, and serverless email notifications keep everyone in the loop.

  • Designed a 10-table relational schema in PostgreSQL — profiles, events, shifts, shift swaps, absence requests, availability rules and overrides, time-off requests, academic terms — with three-tier role-based access (crew / staff / manager) enforced by Row-Level Security on every table.
  • Built recurring weekly availability rules with per-date overrides and academic-term awareness (fall / spring / summer), so schedules follow the university calendar automatically.
  • Implemented a shift-swap workflow as a five-state machine (open → pending → approved / denied / cancelled): crew offer a shift, teammates claim it, managers review — every transition audited with who did what.
  • Added supervisor-tier and split-shift designations on shifts, per-shift attendance tracking (full / split / none), and a dedicated absence-reporting workflow so no-shows and call-outs are logged and reviewed separately from planned time off.
  • Flagged international crew members with an is_international profile attribute tied to office-hours tracking, supporting work-authorization hour-limit compliance.
  • Iterated three serverless notification functions (TypeScript/Deno) across a dozen-plus revisions — shift-assignment alerts, open-shift broadcasts, and scheduled reminders — as the workflow expanded.
  • Onboarded 10 active users across the crew/staff/manager roles, with manager signup gated by an access code.
